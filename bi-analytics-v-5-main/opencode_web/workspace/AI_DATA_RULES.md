# Правила данных для AI (единый источник)

Рабочая директория агента: `/workspace`. База: **`/workspace/web_data.db`** (не каталог `output/`). Активная версия: `web_versions.is_active=1` и `status=success`.

Проверка доступности БД: `python3 /workspace/analytics/inspect_web_db.py` → `output/db_inspect/diagnostics.csv`.

Эталон логики дашборда: `fromsite/.../dashboards/finance_from_1c.py` (скрипты аналитики повторяют её).

---

## 1. Достоверность (критично)

1. **Запрещено придумывать** цифры, %, даты, названия, причины. Только свежий output `analyze_db_*.py` текущего запроса.
2. **Обязательный порядок** перед ответом с цифрами:
   - `python /workspace/analytics/<скрипт>.py`
   - прочитать CSV + `diagnostics.csv` (version_id, число строк, `dashboard_mode_*`)
   - ответ только по этим файлам
3. Если скрипт не запускался, CSV пустой, в таблице маршрутизации «Нет» — ответ: **«По текущим данным в базе ответить нельзя»** + чего не хватает.
4. Запрещены «примерно», «вероятно», «как правило», подмена среза, legacy CSV (`workspace/AI`, `esipovo_deviations*`).
5. `plan_total=0` при `fact_total>0` — не писать «бюджета нет»; в утверждённом бюджете нет строк ПЛАН (см. diagnostics).

## 2. Финансы = как на дашборде

Источник в БД: `reference_dannye` (обороты), `debit_credit` (авансы). Суммы в JSON — **тысячи руб.** → в скриптах **×1000**.

Скрипт: **`python /workspace/analytics/analyze_db_finance_plan_fact.py`**

| Вопрос пользователя | Файл output | Режим дашборда |
|---------------------|-------------|----------------|
| План/факт ₽, %, недоосвоение/перерасход **по проекту** | `plan_fact_by_project.csv` | **Утверждённый бюджет**: ТипСтатьи=БДДС, сценарий ПЛАН (без статей с «(БДР)»), ФАКТ |
| То же **по подрядчику** | `plan_fact_by_contractor.csv` | тот же режим, группировка по Контрагент |
| **Динамика по месяцам / график БДДС** | `plan_fact_by_project_month.csv` | **БДДС синтетика** (данные **есть** в `reference_dannye`, поле `synthetic_monthly_rows` в diagnostics) |
| Почему освоение ниже плана / по статьям | `plan_fact_by_article.csv` | утверждённый бюджет по СтатьяОборотов |
| Авансы, незакрытые остатки | `advances_by_contractor.csv` | debit_credit ×1000 |
| Допустимый объём авансирования | колонка `advance_headroom` | договор − выплачено − остаток |

**Метрики:** `deviation_rub = plan_total - fact_total`. Недоосвоение: `deviation_rub > 0`. Перерасход: `deviation_rub < 0`.

**Не использовать** для рублей: `analyze_db_deviations_for_chat.py` (это сроки MSP в днях), `analyze_db_finance.py` (без ×1000 и без фильтров дашборда).

## 3. Сроки и график (MSP)

| Вопрос | Скрипт |
|--------|--------|
| Отставание по **блоку** | `analyze_db_msp_by_block.py` |
| Просрочки задач, дни, КТ | `analyze_db_project_delays.py` |
| Причины отклонений, доли, pie | `analyze_db_deviations_for_chat.py` |
| Подрядчик отстаёт по блоку | **Нет** (в MSP нет подрядчика в задаче) |
| Причины у подрядчиков | **Нет** (только по проекту: `analyze_db_delay_reasons.py`) |
| РД/ПД, ИД | `analyze_db_rd_registry.py`, `analyze_db_tessa.py`, `analyze_db_tessa_overdue.py` |
| ИД vs объёмы работ | **Нет** |

Фильтры как на дашборде: `file_type=project`, исключить `sample_%`, `new_csv/%`, срез `MAX(snapshot_date)` по проекту, просрочка `deviation_days > 0`.

## 4. Ресурсы (ГДРС)

| Вопрос | Скрипт |
|--------|--------|
| Дефицит/профицит, техника (факт из БД) | `analyze_db_resources.py` |
| Подрядчики, кому увеличить ресурсы | `analyze_db_contractors.py` |


**Сопоставление подрядчиков (как на дашборде ГДРС):**
- План и факт по подрядчикам — только пересечение `other_*_resursi` и справочника `1C_Kontr`.
- Ключ синхронизации: `ID_Контрагента`; если в resursi пусто или `#Н/Д` — по нормализованному наименованию.
- Если в resursi нет ID — подставлять из `Dogovor` с учётом **проекта** (один контрагент на разных проектах).
- В CSV Apr+ имя может быть в колонке `Подрядчик_old`, если `Подрядчик_new` пустой.

План людей/техники на дашборде берётся из **spravochniki** (`max(Количество)` по массивам) — в `web_data` может не быть отдельного file_type; при расхождении плана с порталом указать ограничение.

## 7. Графики (PNG) — только канонические пути

После запуска скрипта вставь в ответ **одну отдельную строку** — точный путь из таблицы (скопируй из `diagnostics.csv` поле `chart_png` или из таблицы ниже).  
**Запрещено** придумывать имена (`budget_plan_fact_*`, `output/budget_*.png` и т.п.).

| Скрипт | Канонический PNG |
|--------|------------------|
| `analyze_db_finance_plan_fact.py` | `/workspace/analytics/output/db_finance_plan_fact/plan_fact_by_project.png` |
| `analyze_db_finance_plan_fact.py` (месяцы БДДС) | `/workspace/analytics/output/db_finance_plan_fact/plan_fact_bddds_monthly.png` |
| `analyze_db_deviations_for_chat.py` | `/workspace/analytics/output/db_deviations_chat/deviations_reasons_for_chat_pie.png` |

Правила:
- PNG должен быть создан скриптом в этом запросе (размер > 0).
- Строка с путём — **отдельная строка**, только путь, без «диаграмма построена», без «(изображения нет)» и без текста после `.png`.
- Не пиши путей Windows (`\workspace\...`) — только `/workspace/...`.
- Если PNG нет — опиши результат текстом/таблицей из CSV, **без** выдуманного пути.

## 8. Ответ пользователю

- Не упоминать скрипты, `web_data.db`, папки output.
- Только итог, без «сейчас проверю» / «запущу анализ» / шаблонного приветствия.
- **Структура:** (1) вывод 1–2 предложения с главной цифрой; (2) таблица markdown до 15 строк **или** нумерованный список из CSV; (3) при необходимости пояснение методики одной фразой (например «утверждённый бюджет БДДС»).
- Цифры, %, названия проектов/подрядчиков — **только** из CSV текущего запуска.
- Типовые вопросы и маршрутизация: `cat /workspace/analytics/QUESTIONS_CATALOG.md` (сопоставление с `questions.md`).
- **Графики (PNG):** не добавлять в ответ, пока пользователь явно не просит диаграмму/график.
